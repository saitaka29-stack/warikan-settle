# 【Claude Code】旅行の割り勘を「最小の送金回数」で精算するアプリ「ワリカンスッキリ」を作った

## 作ったもの
旅行や飲み会で、立て替えた支払いを入力するだけで **「誰 → 誰：いくら」払えば精算が終わるか** を出すWebアプリです。
ログイン不要・インストール不要で、スマホのブラウザからすぐに使えます。

- 公開 URL：https://YOUR-VERCEL-URL.vercel.app
- GitHub：https://github.com/saitaka29-stack/warikan-settle

![スクリーンショット](./screenshot.png)

### できること
- メンバーと支払い（内容・金額・払った人・誰の分か）を登録
- 「お酒は飲んだ人だけで割る」のような **一部のメンバーだけの割り勘** に対応
- 精算リストを表示（4 人なら最大 3 回の送金で完了）
- 結果をコピーして LINE に貼れる／入力内容ごと **共有 URL** で渡せる
- 入力内容はブラウザに自動保存（再読み込みしても消えない）

## 誰のため？
友人・家族・サークルの旅行や飲み会で **幹事をする人** のためのツールです。

「ホテル代はAさん、レンタカーはBさん、夕食はCさん、お酒は飲んだ人だけ…」と立て替えが入り組むと、
最後の精算でスプレッドシートとにらめっこすることになります。全員が全員に送金すると回数も多くなります。
そこで「入力したら精算の答えだけ出る」1 機能特化のアプリにしました。

## 技術スタック
| 分類 | 使用技術 |
|------|----------|
| フロントエンド | React 19 / TypeScript / Vite |
| テスト | Vitest |
| Lint | oxlint |
| 動作確認・スクショ | Playwright |
| ホスティング | Vercel |

**サーバーも DB も使っていません。** データは `localStorage` と URL ハッシュ（`#s=...`）だけで扱うので、
個人の支払い情報が外部に送られることはありません（URL ハッシュはサーバーに送信されない部分です）。

### 精算アルゴリズム
1. 各支払いを対象者で割る。端数は先頭の人から 1 円ずつ配り、**合計が必ず一致**するようにする
2. 一人ずつ「立て替えた額 − 負担額」＝差額を計算（全員の合計は必ず 0）
3. 受け取る人と払う人を金額の大きい順に並べ、最大同士を相殺していく（貪欲法）→ 送金は最大 N−1 回

## 使った Claude Code の機能
### 1. 要件定義書 ＋ `@` 参照
最初に `docs/requirements.md` に「誰の・何を・どう解決するか」「やらないこと」「成功の基準」を書きました。
CLAUDE.md に「要件は docs/requirements.md を正とする」と書き、追加の指示を出すときも `@docs/requirements.md` で
ファイルを直接渡すことで、要件からぶれないようにしています。

### 2. `/init` で CLAUDE.md を生成 → ルールを追記
`/init` でコマンド一覧などの土台を作り、プロジェクト固有のルールを追記しました。特に効いたのはこの 3 つです。
- **バックエンドを追加しない**（データはブラウザ内だけ）
- **計算ロジックは `src/lib/` の純粋関数に置き、変更したら必ずテストを更新**
- **金額は整数（円）で扱い、端数を配っても合計が必ず一致すること**

お金の計算は 1 円ずれるだけで信用を失うので、「合計一致」をルールとして明文化したのがポイントです。

### 3. Plan Mode で設計 → 確認 → 実装
いきなりコードを書かせず、Plan Mode でデータモデル・精算アルゴリズム・保存方式・画面構成・テスト項目・検証方法を
`docs/plan.md` にまとめさせ、内容を確認してから実装に進みました。
実装順も「ロジック＋テスト → UI → E2E 確認」と決めたので、UI を作る前に計算の正しさをテストで保証できました。

### 4. テスト・Lint・ビルドを回しながら実装
`npm test`（10 件）→ `npm run lint` → `npm run build` を通し、最後に Playwright で
「4 人・5 件の支払いを入力 → 精算 → コピー → 再読み込み → 共有 URL で復元」まで実際のブラウザで確認しました。
README のスクリーンショットもこのとき撮影しています。

### 5. Git ワークフロー
要件定義・CLAUDE.md・設計・実装の区切りでコミットし、GitHub に push → Vercel と連携してデプロイしました。

## つまずいたところと解決方法
### ① 日本語を含むデータを共有 URL にすると壊れる
共有 URL は状態を JSON → base64 にしてハッシュに入れていますが、`btoa()` は日本語（マルチバイト文字）を直接扱えず例外になります。
→ `TextEncoder` で UTF-8 のバイト列にしてから base64url に変換するようにし、
「日本語・絵文字を含む状態を encode → decode で復元できる」テストを追加して解決しました。

### ② 割り切れない金額で合計が合わない
10,000 円を 3 人で割ると 3,333.33… 円。四捨五入すると合計が 9,999 円になってしまいます。
→ 全員に切り捨て額を配り、余りを先頭の人から 1 円ずつ配る方式に統一。CLAUDE.md にもルールとして書きました。

### ③ 後から追加したメンバーが「誰の分？」に入らない
最初は「チェックされた人」を状態に持つ設計にしていましたが、これだと支払い入力中にメンバーを追加すると、その人が対象から漏れてしまいます。
→ 「対象から外した人」を状態に持つように反転させ、既定は常に全員が対象になるようにしました。

### ④ 作業セッションが途中で再起動して Plan Mode が解除された
クラウド環境で作業していたため、設計中にセッションが再起動して Plan Mode が抜けてしまいました。
→ 設計内容をプランファイルから `docs/plan.md` にコピーしてリポジトリに残し、それを正として実装を続けました。
CLAUDE.md にも「設計は docs/plan.md を正とする」と書いておくことで、次のセッションでも同じ前提で作業できます。

## まとめ
「1 機能に絞る」「要件定義書と CLAUDE.md でルールを先に決める」「Plan Mode で設計してから実装する」の流れにすることで、
Claude Code に任せる部分が多くても、お金の計算という間違えられない部分をテストで守りながら完成させられました。
