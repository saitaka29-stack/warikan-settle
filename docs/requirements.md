# 要件定義書：割り勘精算アプリ「ワリカンスッキリ」

関連資料：[ユーザーストーリーマップ（T-04）](./user-story-map.md) ／ [情報設計（T-05）](./information-architecture.md)

## 1. プロジェクト概要

### 背景
旅行や飲み会で「A さんがホテル代、B さんがレンタカー代、C さんが夕食代、お酒は飲んだ人だけ…」と
**立て替えが複数人・複数回に分かれる**と、最後の精算が面倒になる。
- 電卓やスプレッドシートでの計算は時間がかかり、1 円単位で間違えやすい
- 素直に計算すると「全員が全員に払う」状態になり、送金回数が多い
- 参加者は「結局自分はいくら、誰に払えばいいのか」が分からず、幹事に何度も聞く
- 既存の割り勘アプリは、アカウント登録・インストール・広告がハードルになることがある

### 目的
- 幹事が **支払いを入力するだけで、最小限の送金回数の精算リスト** を得られる
- 参加者が **リンクを開くだけで、自分の送金額と送金先** がすぐ分かる
- 幹事が **誰の精算が終わったか** を最後まで管理できる

### スコープ
| 含むもの | 含まないもの |
|---|---|
| イベント（旅行・飲み会）単位の管理、複数イベント | ユーザー登録・ログイン |
| メンバー・支払いの登録／編集／削除、一部メンバーだけの割り勘 | 複数端末でのリアルタイム同期（サーバー保存） |
| 精算リスト（最小に近い送金回数）、一人ずつの内訳 | 外貨・為替換算、傾斜配分（v2.0 で検討） |
| テキストコピー・共有 URL・参加者用の閲覧ページ | 実際の送金（PayPay 等との連携） |
| 送金ごとの精算済みチェック | レシート撮影での読み取り |

## 2. ユーザーストーリー

**ペルソナA：幹事**
- As a 幹事, I want 旅行ごとにイベントを作って支払いをまとめられること, So that 複数の旅行や飲み会の精算が混ざらない.
- As a 幹事, I want 誰が何にいくら立て替えたかを、対象メンバーを選んで登録できること, So that 「お酒は飲んだ人だけ」のような割り方も正しく反映できる.
- As a 幹事, I want 最小限の送金回数で済む「誰 → 誰：いくら」のリストを見られること, So that 計算の手間と送金の回数を減らせる.
- As a 幹事, I want 結果を LINE に貼れるテキストや共有リンクで送れること, So that 参加者に説明する手間がなくなる.
- As a 幹事, I want 送金ごとに精算済みのチェックを付けられること, So that 回収し忘れを防げる.
- As a 幹事, I want 登録した支払いを後から直せること, So that 入力ミスがあってもやり直さずに済む.

**ペルソナB：参加者**
- As a 参加者, I want 登録やインストールなしでリンクから精算結果を見られること, So that すぐに確認できる.
- As a 参加者, I want 自分の名前を選ぶと、自分が誰にいくら払うかが大きく表示されること, So that 迷わず送金できる.
- As a 参加者, I want 支払いの明細を確認できること, So that 金額に納得して払える.

## 3. 機能要件

| ID | 機能名 | 説明 | 優先度 | Phase |
|---|---|---|---|---|
| F-01 | メンバー追加・削除 | 名前を入力して追加。削除時、関係する支払いがあれば確認する | 高 | MVP |
| F-02 | 支払い登録 | 内容・金額（円・整数）・払った人・対象メンバー（既定は全員）を登録 | 高 | MVP |
| F-03 | 一部メンバーの割り勘 | 対象メンバーのチェックを外すと、残りの人だけで割る | 高 | MVP |
| F-04 | 支払い削除 | 一覧から削除 | 高 | MVP |
| F-05 | 精算リスト | 最小に近い送金回数（N 人なら最大 N−1 回）の「誰 → 誰：いくら」を表示 | 高 | MVP |
| F-06 | 一人ずつの内訳 | 立て替え額・負担額・差額を表示 | 中 | MVP |
| F-07 | 自動保存 | 入力のたびにブラウザ（localStorage）へ保存 | 高 | MVP |
| F-08 | 結果のテキストコピー | LINE に貼れる形式でクリップボードにコピー | 高 | MVP |
| F-09 | 共有 URL | イベントの内容を URL ハッシュに埋め込んでコピー | 中 | MVP |
| F-10 | イベント作成・一覧・削除 | イベント名を付けて作成。トップに一覧（名前・人数・合計・精算状況） | 高 | v1.0 |
| F-11 | イベント名・メンバー名の変更 | イベント詳細から名前を変更 | 中 | v1.0 |
| F-12 | 支払い編集 | 登録済みの支払いをフォームに呼び出して修正 | 中 | v1.0 |
| F-13 | 精算済みチェック | 送金ごとにチェック。全件済みなら「精算完了」を表示。支払いが変わり送金内容が変わったチェックは外れる | 中 | v1.0 |
| F-14 | 参加者用の閲覧ページ | 共有 URL から開く読み取り専用ページ。名前を選ぶと自分の送金を強調、金額コピー | 高 | v1.0 |
| F-15 | 自分の端末に取り込む | 共有ビューのイベントを自分のイベント一覧に保存（同じイベントは上書き確認） | 低 | v1.0 |
| F-16 | 共有シート | 対応端末では OS の共有シート（Web Share API）で送れる。非対応ならコピー | 低 | v1.0 |
| F-17 | 旧データの引き継ぎ | MVP 版で保存したデータを 1 つのイベントとして読み込む | 中 | v1.0 |
| F-18 | 端数の丸め・外貨・傾斜配分・送金リンク | 将来検討 | 低 | v2.0 |

### 計算ルール
- 金額は **整数（円）** で扱い、小数を経由しない
- 支払いを対象者で割るときは、全員に切り捨て額を配り、余りを対象者の先頭から 1 円ずつ配る → **負担額の合計は必ず支払額と一致**
- 差額（立て替え額 − 負担額）の全員合計は必ず 0。精算リストどおりに送金すると全員の差額が 0 になる

## 4. 非機能要件
- **パフォーマンス**：モバイル回線でも初回表示 3 秒以内（JS は gzip で 100KB 程度に抑える）。入力から精算結果の反映まで体感で遅れがないこと（〜30 人・〜200 件の支払いを想定）
- **セキュリティ・プライバシー**：認証なし。データはブラウザ内（localStorage）と URL ハッシュのみで、**サーバーに送信しない**（ハッシュはリクエストに含まれない）。外部 API・解析タグは使わない。共有 URL を知っている人は内容を見られることを画面に明記する
- **可用性**：Vercel の静的ホスティング（CDN）で配信し、サーバー処理を持たない
- **スケーラビリティ**：サーバー処理がないので、利用者数は CDN 配信でまかなえる
- **ユーザビリティ**：スマホ幅 375px で横スクロールが出ない。ダークモード対応。主要操作は 2 タップ以内
- **品質**：計算・保存ロジックは単体テストで検証する（Vitest）。主要フローは Playwright で動作確認する
- **対応ブラウザ**：最新の iOS Safari / Android Chrome / PC の Chrome・Edge・Safari

## 5. 制約条件
- **予算**：無料枠で完結（Vercel Hobby、GitHub 公開リポジトリ）
- **期間**：課題期間内（MVP は実装済み、v1.0 を追加実装）
- **技術**：React 19 + TypeScript + Vite + Vercel。ルーティングは外部ライブラリを使わず History API で実装し、Vercel の rewrite で SPA にする
  - Supabase などの DB は使わない（ログインなし・個人の金銭情報を預からない方針のため）
- **開発**：Claude Code を使い、CLAUDE.md のルールと Plan Mode（設計 → 確認 → 実装）で進める
